# InterviewOps 面试讲解与演示指南

## 30 秒项目介绍

我做的是 InterviewOps，一个面向技术求职者的面试训练与复盘系统。它不是随机出题的聊天 Demo，而是用候选人画像、目标 JD 和私有项目资料约束问题生成；系统会根据上一题的回答缺口动态追问，并把评分证据、缺失信息和更好的表达结构沉淀为长期复盘档案。底层保留了用户级 RAG、MCP 工具治理、SSE 和可观测性，因此产品场景和工程能力是统一的。

## 这个项目的真实使用背景

技术求职准备通常存在三个断点：

1. 不知道面试官会怎样沿着简历项目连续深挖。
2. 练习后只知道“答得不顺”，不知道具体缺少技术深度、个人贡献还是事实指标。
3. 同样的问题反复犯，复盘没有进入下一轮训练。

InterviewOps 把这三个断点串成“准备资料 → 模拟追问 → 证据评分 → 复盘档案 → 提升计划”的闭环。

## 5 分钟演示脚本

### 1. 备战工作台（30 秒）

说明当前目标岗位、画像完整度、资料数量、训练次数和平均表现。强调首页展示的是用户备战状态，不是通用 Agent 运行监控。

### 2. 目标与画像（40 秒）

填写目标公司、岗位与 JD，解释它们是问题生成器的约束层。个人介绍要求写可验证的经历，不鼓励空泛形容词。

### 3. 面试资料（40 秒）

上传一份 DOCX 简历或 PDF 项目说明，选择“简历 / JD / 项目 / 面试记录”类别。说明文档只提取纯文本、按用户建立向量索引，并保留来源。

### 4. 模拟面试（90 秒）

选择“项目深挖”、进阶难度、2 题：

- 第一题应结合画像/JD/资料，而不是固定八股题。
- 回答时刻意遗漏一个量化指标。
- 展示逐题反馈中的“有效证据”和“可以补强的地方”。
- 点击下一题，证明系统确实围绕上一题的缺口追问。

### 5. 复盘档案（60 秒）

展示 100 分综合表现、1—5 分能力维度、稳定优势、优先补强和逐题证据链。展开某题，让面试官看到原回答、评分证据和建议结构都可核验。

### 6. 工程能力（40 秒）

展示测试与评测命令：

```bash
npm run check
npm run eval:interview
npm run eval:tools:dry
```

再说明评分 JSON 合同、服务端聚合、用户隔离、原子写入和 Agent 工具治理。

## 面试官最值得看到的四个设计

### 1. 场景层和通用 Agent 层没有耦死

面试领域被拆成 store、rubric、service、routes。DeepSeek 和 RAG 通过依赖注入传给 service，因此测试可以用假模型和假检索，不需要网络或 API 费用。通用 Agent 仍负责公司调研、资料问答和任务写入。

### 2. 动态追问不是一次生成一组题

每次回答完成后，服务会把当前问题、候选人回答和缺失点作为下一题上下文。这样可以模拟真实面试的追问链，也能解释为什么问题与候选人相关。

### 3. 总分不由模型随意计算

模型只返回各维度 1—5 分和证据；服务端负责分数裁剪、字段归一化、维度平均和 100 分换算。合同回归集覆盖四种当前模式、两种历史兼容模式和越界分数，防止 Prompt 或模型升级破坏数据结构。

### 4. 数据边界是服务端能力

JWT 只在 API 解析，用户身份不会暴露给模型。画像与训练记录使用用户 ID 的 SHA-256 摘要作为文件名，RAG、记忆、待办和笔记同样按用户过滤；画像、训练记录与 RAG 索引使用临时文件 + rename，降低中途损坏风险。

## 高频追问

### 为什么不是直接接入一个模拟面试 API？

这个项目想展示的是如何把个人资料、动态追问、证据评分和长期复盘组合为产品闭环。外部 API 能减少模型调用代码，但无法替代领域状态机、用户数据边界、评分合同和可解释复盘。

### 如何避免模型替候选人编经历？

评估 Prompt 要求只引用回答中的事实，输出里把 evidence 和 missingPoints 分开。前端保留原回答并展示证据列表，用户可以检查模型是否越界。更严格的版本可以加入 evidence span 对齐校验。

### 分数可靠吗？

它是训练反馈，不是真实录用标准。当前保证的是评分结构稳定、证据可检查、同一模式维度一致；下一步会建设人工标注集，测量与面试官评分的一致性，并针对模型和 Prompt 做版本化回归。

### 为什么持久化还用 JSON？

当前目标是个人演示和关键链路验证，本地 JSON 降低部署门槛。代码已经把存储封装在 store 层，生产化可以替换为 PostgreSQL；向量索引迁移到 pgvector/Milvus，接口和领域服务无需整体重写。

### 为什么保留 MCP 和通用工具？

面试准备仍需要实时公司调研、资料检索、笔记和提升计划。MCP 负责工具协议，catalog 负责 schema、scope、timeout 和服务端身份注入，两者属于基础设施层，不应因为产品聚焦而删除。

## 简历项目描述（按实际结果继续量化）

**InterviewOps｜面试训练与复盘智能体**

- 设计并实现面向技术求职者的 AI 面试闭环，结合候选人画像、目标 JD 与用户级 RAG 生成针对性问题，以综合模拟、项目深挖、岗位专项与行为面试覆盖不同训练目标，并根据任意岗位动态约束技术方向。
- 构建结构化评分合同与服务端确定性聚合，输出回答证据、缺失点、表达结构、能力维度和 100 分复盘报告；将 store/rubric/service/routes 解耦并通过依赖注入实现无网络单测。
- 实现 DOCX/PDF/文本资料解析、分块、BGE-M3 向量索引和来源引用；以 JWT 服务端身份注入隔离画像、会话、RAG、Memory、Todo 与 Note 数据。
- 保留并治理 10 个 Agent 工具，支持 MCP、SSE 工具状态、Prometheus 指标、工具路由评测与 CI 质量门禁。
